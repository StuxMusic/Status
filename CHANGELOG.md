# Changelog

All notable changes to Stux.Music's status page (status.stux.music) are documented here. It
follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Since v26.10.23 this project uses [Date Versioning](https://datevers.ing) (`YY.MM.DD`, the UTC release date, with `-1`, `-2`… for later releases the same day); earlier releases used Semantic Versioning.

## v26.10.23

### Added

- `tests/version.sh`, which checks that `VERSION.md` is a valid Date Version, a real calendar date not in the future, and the same as the newest entry in this changelog

### Changed

- Switched from Semantic Versioning to [Date Versioning](https://datevers.ing): releases are numbered by their UTC release date as `YY.MM.DD`, with `-1`, `-2`… for later releases the same day. This release follows v1.0.3
- `commit.sh` and `commit.bat` refuse a `VERSION.md` that isn't a valid Date Version or is dated in the future (UTC), and warn when it's dated before today
- `README.md` and `CONTRIBUTING.md` describe Date Versioning and the release steps

## v1.0.3

### Changed

- The logos and icons in the Markdown docs (README and the like) follow GitHub's light or dark theme, using each brand's `logo-light`/`logo-dark` and `icon-light`/`icon-dark` files

## v1.0.2

### Changed

- `max_response_time` raised to 15 seconds (GitHup's new default), so a slow but working site is no longer shown as degraded

## v1.0.1

### Fixed

- Sharp.Stux.Music is checked on a release page (`/human-enlightenment`) instead of its index, which sometimes redirects to stuxsharp.com (history is kept)

## v1.0.0

### Added

- The Stux.Music status page, built with GitHup and deployed to GitHub Pages at status.stux.music
- Monitors for the Stux.Music website, the artist directory, Stux Sharp's sites, the Artistpage, Soonpage and Maintenancepage templates and the Stux.Music media CDN
- Boring Legal Stuff hub with its six sub-pages, a 404 page, a sitemap and `robots.txt`, generated by GitHup
- A 5-minute check with `fill-gaps` (up to 4 checks, 5 minutes apart, when GitHub runs the schedule late), incident Issues, and an hourly rebuild
- `dev-server` (with `DEV_MODE` on by default and `--no-dev-mode`) and `commit` scripts
