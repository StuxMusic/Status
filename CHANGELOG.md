# Changelog

All notable changes to Stux.Music Status (status.stux.music) are documented here.

Since v26.10.23 this project uses [Date Versioning](https://datevers.ing) (`YY.MM.DD`, the UTC release date, with `-1`, `-2`… for later releases the same day); earlier releases used Semantic Versioning.

## v26.11.08

### Changed

- The status page's description, the `.githup.yml` comment and the README say monitors are "checked regularly"
  instead of "every 5 minutes": GitHub runs the `*/5` schedule on a best-effort basis, often only every few hours. The
  workflow's cron comment says so, and the page's "Updated" line (GitHup v26.11.08) now shows the measured rhythm

## v26.11.07

### Changed

- The copyright holder is Stux.Music rather than Stux.Group, in `LICENSE` and `README.md`

## v26.11.06-2

### Added

- A `test` branch: work happens there (or on a branch off it), and changes reach `main` only through a pull request from `test`, reviewed and merged by Leo. CONTRIBUTING has a new Branches section, and the README's Versioning section says so
- A CI workflow (`.github/workflows/ci.yml`) running `tests/version.sh` on pushes to `main` and `test` and on pull requests, so a pull request into `main` has a check to pass
- Monitors for Stux Sharp Media CDN (sharp.media.stux.music, which serves Stux Sharp's covers and logos) and the Stux.Music GitHub Pages Redirect (stuxmusic.github.io), so every live Stux.Music site is checked

### Changed

- `commit.sh` and `commit.bat` say to push `test` with its tags and open a pull request into `main`, instead of pushing `main`

## v26.11.06-1

### Changed

- `CONTRIBUTING.md` is titled Stux.Music Status, and asks for full monitor names and a pinned `slug:` when renaming one

### Fixed

- The CHANGELOG intro said this project follows Semantic Versioning, then that it uses Date Versioning; it now says only
  the latter (with earlier releases on Semantic Versioning)

## v26.11.06

### Changed

- The page's logo and favicon are its own badge icon (the Stux.Music mark with a heartbeat badge, built by
  StuxMusic/Artists' `scripts/badge-icons.py` and hosted on artists.stux.music) rather than the plain Stux.Music logo
  and icon. The README's header too, now titled Stux.Music Status
- Every monitor uses its full name: Artists, Artistpage, Soonpage and Maintenancepage are now Stux.Music Artists,
  Stux.Music Artistpage, Stux.Music Soonpage and Stux.Music Maintenancepage. Their slugs are pinned to the old ones,
  so their history, incident labels and the Artists site's live badges carry on
- `commit.sh`, `commit.bat`, `dev-server.sh` and `dev-server.bat` call the project Stux.Music Status

## v26.10.23

### Added

- `tests/version.sh`, which checks that `VERSION.md` is a valid Date Version, a real calendar date not in the future, and the same as the newest entry in this changelog

### Changed

- Switched from Semantic Versioning to [Date Versioning](https://datevers.ing): releases are numbered by their UTC release date as `YY.MM.DD`, with `-1`, `-2`… for later releases the same day. This release follows v1.0.3
- `commit.sh` and `commit.bat` refuse a `VERSION.md` that isn't a valid Date Version or is dated in the future (UTC), and warn when it's dated before today
- `README.md` and `CONTRIBUTING.md` describe Date Versioning and the release steps

## v1.0.3

### Changed

- The logos and icons in the Markdown docs (README and the like) follow GitHub's light or dark theme, using each brand's `logo-light`/`logo-dark` and `icon-light`/`icon-dark` files

## v1.0.2

### Changed

- `max_response_time` raised to 15 seconds (GitHup's new default), so a slow but working site is no longer shown as degraded

## v1.0.1

### Fixed

- Sharp.Stux.Music is checked on a release page (`/human-enlightenment`) instead of its index, which sometimes redirects to stuxsharp.com (history is kept)

## v1.0.0

### Added

- The Stux.Music status page, built with GitHup and deployed to GitHub Pages at status.stux.music
- Monitors for the Stux.Music website, the artist directory, Stux Sharp's sites, the Artistpage, Soonpage and Maintenancepage templates and the Stux.Music media CDN
- Boring Legal Stuff hub with its six sub-pages, a 404 page, a sitemap and `robots.txt`, generated by GitHup
- A 5-minute check with `fill-gaps` (up to 4 checks, 5 minutes apart, when GitHub runs the schedule late), incident Issues, and an hourly rebuild
- `dev-server` (with `DEV_MODE` on by default and `--no-dev-mode`) and `commit` scripts
